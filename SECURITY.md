# Политика безопасности: Chronos Team 2.0

**Статус:** локальный учебный прототип. Без авторизации, не предназначен для персональных данных реальных сотрудников или публикации в Интернете.

## Границы доверия

- Доверенная среда: localhost/127.0.0.1, локальный администратор, локальная SQLite-база.
- Недоверенные данные: JSON-ввод, заголовки и query-параметры HTTP, содержимое старой БД, импортированные описания задач.
- Недоверенное окружение: сайты, открытые в браузере пользователя, внешние приложения в локальной сети, любой пользователь с доступом к локальной машине.
- Резервные копии содержат данные сотрудников. Они не шифруются приложением; храните их с ограниченными правами доступа.

## Защитные меры (не абсолютные гарантии)

1. Только локальное связывание `uvicorn --host 127.0.0.1` и Docker-порт `127.0.0.1:8000`.
2. `TrustedHostMiddleware` и явный список допустимых Host из `CHRONOS_ALLOWED_HOSTS`.
3. Для изменений необходимо `X-Chronos-Request: 1` и проверка `Origin`/`Referer`/`Sec-Fetch-Site`; CORS не разрешён.
4. Серверная валидация Pydantic с `extra='forbid'`, ограничения длины, категорий, идентификаторов, времени и Unicode control characters.
5. Параметризованные SQL-запросы, FK, уникальный индекс активного таймера, транзакции и откат при ошибке.
6. Ограничение тела изменяющего API-запроса до 16 KiB, выборки отчёта до 20 000 записей, максимальный период 371 день, лимит журнала 500 событий.
7. Строгий CSP и ограничивающие заголовки, экранирование полей в DOM, защита экспорта CSV от формул.
8. Локальный журнал правок, согласованные резервные копии SQLite через `sqlite3.backup`.
9. Нет сетевых библиотек и сторонних JS-CDN на стороне клиента.

## Известные непринятые риски

- **КРИТИЧЕСКИЙ для публичного развёртывания:** нет аутентификации, авторизации и разделения прав. Любой субъект с локальным доступом к API может изменить или удалить записи. Ни защита от CSRF, ни Host allowlist этого не исправляют.
- Журнал аудита не идентифицирует исполнителя, не имеет криптографической защиты от администратора базы и не заменяет внешнюю систему логирования.
- Нет самостоятельного TLS-сервера и централизованного журнала запросов, политики хранения персональных данных, антивирусного/пенетрационного аудита, multi-tenant изоляции.
- SQLite поддерживает много одновременных читателей, но только одного активного писателя; нагрузочный бенчмарк и SLA не установлены.
- JS-оболочка допускает только отдельные тесты доступности; полная сертификация WCAG 2.2 отсутствует.
- Полный скан зависимостей на актуальные CVE и анализ контейнера не были выполнены в этой среде.

## Сообщение об уязвимости

Не публикуйте в открытых issues реальные секреты, записи сотрудников или приватные пути. Передавайте техническое описание уязвимости владельцу репозитория через частный канал. У прототипа нет SLA реагирования и назначенного security team.

Ориентиры: [OWASP ASVS 5.0](https://asvs.owasp.org/), [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html), [NIST SP 800-218](https://csrc.nist.gov/pubs/sp/800/218/final).
