REST API · v2.0

Документация API

Локальное API учёта рабочего времени. Все данные передаются в JSON; временные интервалы используют Unix timestamp в миллисекундах. Эта документация работает без подключения к внешним CDN.

Открыть OpenAPI JSON

Для каждого POST, PUT и DELETE запроса обязателен HTTP-заголовок X-Chronos-Request: 1. Для JSON с телом — Content-Type: application/json. Это защита локального приложения от обычных CSRF-форм, но не полноценная авторизация.
Без аутентификации: интерфейс и API предназначены только для локального тестирования. Не публикуйте приложение в Интернет без защиты доступа.

Сотрудники

GET /api/employeesСписок сотрудников и активных таймеров
POST /api/employeesДобавить сотрудника
PUT /api/employees/{employee_id}Изменить ФИО, должность и часовую норму
{"full_name":"Алексей Миронов","position":"Тестировщик","weekly_target_hours":40}

Таймеры и журнал

POST /api/timers/startЗапуск (409, если таймер уже активен)
{"employee_id":1,"description":"Проверка формы","category":"Тестирование"}
POST /api/timers/{employee_id}/stopОстановить текущий таймер сотрудника
PUT /api/entries/{entry_id}Изменить описание и категорию
DELETE /api/entries/{entry_id}Удалить завершённую запись

История изменений

GET /api/audit?limit=100&employee_id=1Последние изменения, включая значения до и после (до 500 событий на запрос)

Отчёт и мониторинг

GET /api/report?start_ms=...&end_ms=...&tz=Asia/DushanbeПериод [начало, конец) и необязательный employee_id
GET /api/healthПроверка доступности SQLite-хранилища

Ошибки валидации возвращают HTTP 422, отсутствующие сущности — 404, конфликт таймеров — 409. Ограничение размера отчёта — 20 000 записей (при превышении HTTP 413); для POST/PUT допускается тело до 16 KiB. Полный OpenAPI доступен по ссылке выше.
